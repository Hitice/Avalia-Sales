Avalia Sales: a stack em produção

Uma venda, de ponta a ponta

Cancelar um item devolve só a parte dele, por estorno parcial no Pagar.me.

  1. BalcãoO vendedor escolhe os itens e lê o QR da placa
  2. POST /vendas/itensUma cobrança para todos os itens
  3. Cobrança gravadaAntes do gateway, com o próprio id como código do pedido
  4. Pagar.meGera o Pix com split
  5. Cliente pagaO Pix na tela do vendedor
  6. WebhookGrava o evento uma vez (ON CONFLICT DO NOTHING)
  7. WorkerFOR UPDATE SKIP LOCKED e reconsulta a fonte
  8. RazãoSó inserção: receita, taxa, comissão; ordem de serviço quando há serviço
  9. pg_notifyNo commit, para o SignalR
  10. Pagamento confirmadoA tela do vendedor atualiza sem recarregar

Camadas

Back-end

  • C# e .NET 10. Domain sem dependência, Application só com interfaces, Infrastructure, Api
  • EF Core 10 + Npgsql
  • Identity + JWT HMAC-SHA256 de 15 min. Refresh rotativo em cookie HttpOnly: token reapresentado derruba a sessão
  • Polly só em método seguro
  • ProblemDetails 422 para regra recusada

Front-end

  • React 19, Vite, TypeScript
  • React Router por papel
  • TanStack Query, invalidado pelo aviso ao vivo
  • Zustand com o token só em memória
  • React Hook Form + Zod
  • Tailwind 4 + shadcn/ui
  • Tipos gerados do OpenAPI; divergência quebra o CI
  • QR pela câmera, NFC pelo Web NFC

Dados

  • revendedor_id + filtro global do EF + RLS forçado; papel sem BYPASSRLS
  • Teste falha se tabela nova nascer sem RLS
  • Dinheiro em centavos bigint, taxa em pontos base
  • Razão só de inserção com índice único; fechamento do mês por trigger
  • Índices parciais na fila
  • DRE com a receita da placa reconhecida em 12 partes

Infra

  • Docker Compose, 8 serviços: nginx, api, worker, migrar, postgres, gotenberg, certbot, backup
  • Ubuntu 24.04; aplicação sem root
  • Segredos só no servidor e no ambiente do GitHub

Segurança e LGPD

  • Bloqueio após 5 erros; 2FA por TOTP ou e-mail
  • Cartão tokenizado no navegador
  • Webhook conferido por HMAC ou segredo, com reconsulta na fonte
  • Auditoria só de inserção
  • Revendedor controlador, plataforma operadora; exportação em JSON e anonimização
  • Sentry sem dado pessoal

Qualidade e método

  • ADRs no formato MADR
  • Documentação cobrada pelo CI nos pull requests
  • Erro de produção chega pelo Sentry, vira teste que reproduz, e o commit da correção fecha o alerta

As telas

Dados de demonstração, revenda fictícia.
